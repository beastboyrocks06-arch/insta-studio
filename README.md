# Instagram Publisher

A private React + Vite and Express app for signing in, connecting Instagram professional accounts, and publishing up to five separate Reels in one batch, single images, or mixed image/video carousels to selected accounts. Media uploads are signed by the server and sent directly to Cloudinary. Neon PostgreSQL persists login sessions, connected Instagram account tokens, and publishing history across restarts and redeploys.

## Flows (set `META_LOGIN_TYPE`)

| | `instagram` (default) | `facebook` |
|---|---|---|
| Authorize | `https://www.instagram.com/oauth/authorize` | `https://www.facebook.com/{ver}/dialog/oauth` |
| Token exchange | `POST https://api.instagram.com/oauth/access_token`, then `GET https://graph.instagram.com/access_token?grant_type=ig_exchange_token` | `GET https://graph.facebook.com/{ver}/oauth/access_token` (+ `fb_exchange_token`) |
| Account lookup | `GET https://graph.instagram.com/{ver}/me?fields=user_id,username` | `GET /me/accounts?fields=...instagram_business_account{id,username}` (uses the Page token) |
| Publish host | `graph.instagram.com` | `graph.facebook.com` |
| Scopes | `instagram_business_basic`, `instagram_business_content_publish` | `pages_show_list`, `pages_read_engagement`, `instagram_basic`, `instagram_content_publish` |

Both flows publish the same way: `POST /{ig-id}/media` (`media_type=REELS`, `video_url`, `caption`) -> poll `GET /{container-id}?fields=status_code,status` until `FINISHED` -> `POST /{ig-id}/media_publish`.

These endpoints and scopes are from my knowledge of Meta's docs, not verified live. Check them against developers.facebook.com before relying on them; Meta changes versions and scope names.

## Setup

1. Install Node.js 20+.
2. `npm run install:all`
3. Create the Meta app at developers.facebook.com/apps (type: Business).
   - **Instagram Login:** add the product *Instagram* -> *API setup with Instagram login*. Add your redirect URI under *Business login settings*. Copy the **Instagram app ID/secret** shown there (these differ from the main app ID/secret) into `META_APP_ID` / `META_APP_SECRET`.
   - **Facebook Login:** add *Facebook Login for Business* (or Facebook Login) and put the redirect URI under *Valid OAuth Redirect URIs*. Your Instagram account must be Business/Creator and linked to a Facebook Page you manage.
4. Your Instagram account must be a **professional** (Business or Creator) account.
5. While the app is in **Development mode**, only people with a role on the app (add your test account under App roles / Instagram testers, and accept the invite) can authorize. Serving other accounts requires App Review and Advanced Access for the publish permission.
6. In Neon, create a PostgreSQL project and run the SQL in [`database/schema.sql`](./database/schema.sql) once in its SQL Editor.
7. Copy `.env.example` to `.env` and set `APP_USERNAME`, `APP_PASSWORD`, `DATABASE_URL`, `META_APP_ID`, `META_APP_SECRET`, and `META_LOGIN_TYPE`. Set the three `CLOUDINARY_*` values for uploads.
   - Copy the Neon connection string into `DATABASE_URL`.
8. Redirect URI (must match the dashboard and `.env` character for character):

       http://localhost:5000/api/auth/callback

   If you change `PORT`, update `META_REDIRECT_URI` and the dashboard to match. Some Meta products require HTTPS redirect URIs even for localhost; if so, use an HTTPS tunnel and set `META_REDIRECT_URI`, `BACKEND_URL` and `FRONTEND_URL` accordingly.
9. `npm run dev`, then open http://localhost:5173

## Using the publisher

1. Sign in with `APP_USERNAME` and `APP_PASSWORD`.
2. Open **Accounts** and connect one or more Instagram professional accounts using Meta OAuth.
3. On **Create post**, choose Reels, Image, or Carousel; select up to five videos (each publishes as a separate Reel) and choose the target account(s) for each video, one image, or 2–10 carousel images and/or videos; select target accounts for images/carousels; optionally add a caption; and choose **Publish now**.
4. Files upload directly to Cloudinary using a short-lived signature generated by the server. Instagram then fetches the Cloudinary URLs to process the media.
5. A CSV is downloaded after a publish run. On the Accounts page, choose optional start and end published dates to download the matching history from Neon, with the date, account, media type, post URL, and media ID for each successful publish. Leave both dates empty to download all history.

Reel video URLs must be publicly fetchable by Instagram (H.264/AAC, vertical 9:16 recommended). Each selected video is published as a separate Reel only to its assigned accounts. Carousel videos and images are published together in the selected order. Posts publish sequentially per selected account; individual failures are reported without preventing attempts for other videos or selected accounts.

## Security notes

- Meta app secret, Cloudinary API secret, and Instagram access tokens never leave the server. Cloudinary API keys and signed upload parameters are returned only to the authenticated browser to upload files directly.
- OAuth `state` is random, tied to the session cookie, single-use, expires after 10 minutes, and compared in constant time.
- The app login credentials are configured with `APP_USERNAME` and `APP_PASSWORD`. No Instagram passwords are collected.
- Sessions and connected accounts persist in Neon. Instagram access tokens can still expire or be revoked by Meta; reconnect an account if Meta invalidates its authorization. Use HTTPS and secure cookies when deploying publicly.
- Never commit `.env`. The `.env.example` file contains placeholders only.

## Common errors

- *Invalid redirect_uri*: dashboard URI differs from `META_REDIRECT_URI`.
- *Permission/“not authorized”*: account isn't a tester/role holder, or lacks the publish permission/Advanced Access.
- *No Page with linked Instagram account* (Facebook flow): link the IG account to a Page and grant that Page at login.
- Container `ERROR`: unsupported codec/size/duration or the URL isn't publicly fetchable.
- *Cloudinary upload is not configured*: set `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` in `.env`.
- *Neon database is not configured*: set `DATABASE_URL` to the Neon PostgreSQL connection string and run [`database/schema.sql`](./database/schema.sql) once in Neon.
